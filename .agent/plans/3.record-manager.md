# Module 3: Record Manager

**Complexity:** ✅ **Simple** - Single-pass executable, low risk

## Overview

Implement content hashing to detect duplicate documents and only process new/modified files. This prevents redundant embeddings and saves resources.

## Problem

Without record management:
- Uploading the same file twice creates duplicate chunks
- Modifying a file and re-uploading doesn't clean old chunks
- No way to track what's already been processed

## Solution

1. **Content Hash**: SHA-256 hash of file content
2. **Deduplication**: Check hash before processing
3. **Change Detection**: If hash changed, delete old chunks and reprocess

## Implementation

### 3.1 Add content_hash to documents table
```sql
ALTER TABLE documents ADD COLUMN content_hash TEXT;
CREATE INDEX idx_documents_content_hash ON documents(content_hash);
```

### 3.2 Create hashing service
- Hash file content on upload
- Compare with existing documents for same user
- Return existing doc if hash matches

### 3.3 Update upload endpoint
- Check for existing document with same hash
- If exists and unchanged, skip processing
- If exists but file path changed, update record
- If new, process normally

### 3.4 Handle updates
- If re-uploading modified file (same filename, different hash):
  - Delete old chunks
  - Update document record
  - Process new content

## Validation

1. Upload file → hash stored
2. Upload same file → skipped (no duplicate)
3. Modify file, upload again → old chunks deleted, new chunks created
4. Check database → only one document per unique content
